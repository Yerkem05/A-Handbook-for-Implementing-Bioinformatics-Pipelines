Chapter: Project Directory Setup

How to create a clean, reproducible folder structure for an ATAC-seq analysis project on Unix-like systems (macOS, Linux, or WSL).

Why structure your project?

A consistent directory layout keeps your files organized, makes pipelines reproducible, and helps collaborators (or future you!) understand where data, scripts, references and results live. The layout below is minimal but practical for most ATAC-seq pipelines.

Commands — create the directory tree

Run the following commands in your terminal. They create the project root and a set of subfolders for raw data, references, scripts, logs, metadata, and some results folders.

# start in your home directory (optional)
cd
pwd

# create the project folder and enter it
mkdir atacseq
cd atacseq

# create main subfolders
mkdir raw_data reference_data scripts logs meta

# create results subfolders (use -p to make parent 'results' if it doesn't exist)
mkdir -p results/fastqc results/bowtie2

# Optional: show the full structure (recursive)
ls -R
Tip: run these commands from your home directory or wherever you keep your projects.

What each command does (plain English)

cd
Change directory. With no arguments it takes you to your home folder (e.g., /Users/yourname).
pwd
Prints the current working directory — useful to confirm you are in the expected location.
mkdir atacseq
Creates a new folder named atacseq — this will be your project root.
cd atacseq
Enter the project directory so all subsequent commands operate inside it.
mkdir raw_data reference_data scripts logs meta
Creates several subfolders:
  • raw_data — store raw FASTQ files here.
  • reference_data — reference genomes, indexes, annotations.
  • scripts — pipeline scripts, helper scripts.
  • logs — log files from runs (stdout/stderr) for reproducibility and debugging.
  • meta — sample sheets, metadata, README files.
mkdir -p results/fastqc results/bowtie2
The -p flag creates parent directories as needed (here, results), then the child folders fastqc and bowtie2. These store pipeline outputs (QC reports, aligner outputs).
ls -R
Lists directory contents recursively so you can confirm the structure (subfolders inside results, etc.).

Example directory tree (expected output)

logs/ raw_data/ reference_data/ results/ scripts/ meta/
./results:
  bowtie2/ fastqc/

If you run ls -R you should see a top-level listing and then the ./results children (fastqc, bowtie2).

Best practices & notes

  • Keep raw data read-only: Never overwrite files in raw_data. Use copies if you need to transform files for tests.
  • Use meaningful names: Name files and sample sheets clearly (e.g., sample01_rep1_R1.fastq.gz).
  • Store commands and environment info: Save the exact commands and Conda/Container environment YAMLs in meta to improve reproducibility.
  • Logs: Redirect tool output to logs/toolname_timestamp.log to capture warnings and errors for debugging.
  • Version control: Keep scripts under Git in scripts/ and add a top-level README.md describing the layout and usage.

Troubleshooting

Permission errors: If you see "permission denied" while creating folders, check you are not trying to write to a protected directory. Use chmod or create the project under your home directory.
Folder already exists: If mkdir fails because a folder exists, either remove it (careful) or use mkdir -p which won't error for existing paths.
