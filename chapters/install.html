Conda setup on macOS (Apple Silicon)

This chapter walks you through installing Miniconda, configuring Bioconda channels, creating an isolated environment for bioinformatics tools, and verifying everything works. Explanations are detailed and concrete so a researcher with little command-line experience can follow along.

Why use Conda + Bioconda?

Conda is a package and environment manager that solves complicated software dependencies for you. Bioconda is a community channel containing thousands of bioinformatics packages (samtools, fastqc, seqtk, etc.). Using Conda + Bioconda lets you install these tools reliably without manual compilation or conflicting library versions.

  • Isolated environments prevent tools from clashing with each other.
  • Reproducibility: share an environment file so others can recreate your software stack exactly.
  • Simplicity: most tools install with one command.

Step 1 — Install Miniconda (Apple Silicon)

Open the Terminal app, then run these commands exactly. They download the installer and run it.

curl -O https://repo.anaconda.com/miniconda/Miniconda3-latest-MacOSX-arm64.sh
bash Miniconda3-latest-MacOSX-arm64.sh
When the script runs, follow prompts. Accept license, choose install location (default is fine), and allow initialization when asked.

Tip: If your Mac uses Intel (older Macs), use the x86 installer instead — ask me and I’ll add that command.

Step 2 — Initialize Conda in your shell

After the installer finishes, either close & re-open Terminal or run the command for your shell:

# for zsh (default on recent macOS)
source ~/.zshrc

# or for bash
source ~/.bash_profile

# check conda works
conda --version

Expected output: something like conda 23.9.0. If you see an error, check the installer output to confirm initialization was allowed or manually add conda to your PATH following the installer's instructions.

Step 3 — Configure Bioconda channels (correct order)

Channel order matters. The recommended order is: conda-forge → bioconda → defaults with strict channel priority. This ensures packages built for conda-forge are preferred while allowing bioconda packages to resolve correctly. 

conda config --add channels conda-forge
conda config --add channels bioconda
conda config --add channels defaults
conda config --set channel_priority strict

# verify
conda config --show channels

What you should see:

channels:
  - conda-forge
  - bioconda
  - defaults

Why strict priority? It prevents mixing incompatible builds from different channels and makes dependency resolution more reliable.

Step 4 — Create a dedicated environment for tools

Never install many tools into the (base) environment. Create an environment named bio-tools for our small test set (seqtk + fastqc):

conda create -n bio-tools -c bioconda seqtk fastqc

# accept prompts (type y then Enter)
conda activate bio-tools

After activation you should see your prompt change from (base) to (bio-tools).

Useful environment commands

# list environments
conda env list

# export environment to a YAML file for reproducibility
conda env export --name bio-tools > meta/bio-tools-env.yml

# remove environment (if broken)
conda deactivate
conda remove -n bio-tools --all

Step 5 — Test installation

Try running the tools you installed to verify they work:

seqtk --help
fastqc --version

If you see usage text for seqtk and a version line for fastqc, you are ready.

Troubleshooting & notes

  • If conda command not found: re-open Terminal or run source ~/.zshrc (or the shell file the installer modified).
  • Package not found: ensure channels are in the right order and run conda config --show channels.
  • Solver takes long / fails: try creating smaller environments, avoid mixing pip-installed system Python packages inside conda envs for complex bio packages.
  • Disk space: conda environments can be large; check free disk space with df -h.
